# Hiring Stall Alerter

A small, local hiring-pipeline dashboard built with **ChatGPT-assisted Python + Streamlit**. Import a CSV, set a threshold, and get a prioritized list of stalled candidates and recommended follow-ups. All candidate examples are fictional.

## Features

- Load a built-in 25-candidate sample or upload your own CSV.
- Change the analysis date and inactivity threshold (1–30 days).
- Skip closed stages (Hired, Rejected, Withdrawn, Closed, Declined, Not selected).
- Rank active candidates and explain each flag in one sentence.
- Recommend a stage-specific next action, filter, and export a follow-up CSV.
- Show input warnings for missing/invalid dates and duplicate candidate IDs.
- No automated messages sent; humans review every action.

## Get started on Windows

1. Install Python 3.11 or newer from https://www.python.org/downloads/ if needed. If offered, enable **Add Python to PATH**.
2. Unzip this folder. Open the folder and double-click **`start_windows.bat`**. Your internet connection is needed on the first run to install packages. A browser page should open when the app starts.
3. Leave the command window running while using the app. Close it when done.

### Manual setup (PowerShell or Windows Terminal)

Open a terminal *inside this unzipped folder*, then run:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

If `py` is not recognized, use `python -m venv .venv` for the first command. The app normally opens at `http://localhost:8501`.

## Use it

1. Pick **Try example data** to immediately test the dashboard.
2. Set the *Analyze as of* date and the *Flag after this many days* threshold in the sidebar. Sample dates are anchored to **2026-11-17**; use that date to reproduce the initial example.
3. Review the metrics and the **Follow-up queue**. The first row is the highest priority by the rules.
4. Filter by priority or search for a role/name.
5. Click **Download prioritized follow-up CSV** for a report.
6. Choose **Upload a CSV** when ready to try your own fictional hiring board.

## CSV format

Required header, in any order (extra columns are ignored):

```csv
candidate_id,candidate_name,role,stage,last_stage_change,owner
C001,Alex Torres,Support Specialist,Interview,2026-11-08,Robin Cruz
```

Dates must be `YYYY-MM-DD` and candidate IDs unique. `role` and `owner` values may be blank; candidate ID, name, stage, and date cannot. Use **CSV UTF-8** if exporting from Excel.

## Rules used by the app

A candidate is flagged if `(analysis_date - last_stage_change).days >= threshold_days` and the stage is active.

- **Urgent:** at least 7 days beyond the limit; or in Offer/Final Interview at least 3 days beyond.
- **High:** at least 3 days beyond; or in Offer/Final Interview at the limit.
- **Follow up:** all remaining flagged candidates.
- Sort by priority first, then the most days beyond the limit, then by stage (Offer, Final Interview, Interview, Assessment, Screening, Applied).
- Next actions are a transparent lookup by stage, not speculative messages generated by AI.

This is a demonstration, not a hiring decision system. Do not use the priority list to make hiring decisions, score applicants' suitability, or automate outreach. Avoid entering real personal information unless you have authorization and a suitable privacy process.

## Run tests

From the project folder:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

This tests CSV validation, inactive/active stage filtering, date thresholds, ordering, and follow-up recommendations.

## Known limitations / next improvements

- CSV-only, one-off upload (no live ATS connection).
- Candidate inactivity is measured only from the `last_stage_change` date.
- The dashboard does not change ATS records or notify candidates.
- Priority rules are configurable in code, but not through the UI.
- Later improvements: configurable stage thresholds, owner-specific queue, history tracking and optional human-reviewed AI draft emails.
